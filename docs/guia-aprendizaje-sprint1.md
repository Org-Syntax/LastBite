# Guía de Aprendizaje - Sprint 1: Módulo Core de LastBite

## 1. Identificación del Programa y Proyecto
* **Programa de Formación:** Técnico / Tecnólogo en Análisis y Desarrollo de Software (ADSO).
* **Centro de Formación:** Centro de Teleinformática y Producción Industrial (CTPI) - SENA Regional Cauca.
* **Proyecto Formativo:** LastBite – Marketplace de Excedentes de Comida Local.
* **Fase del Proyecto:** Ejecución / Desarrollo de Software.
* **Duración Estimada:** 4 Semanas (40 Horas de formación directa y autónoma).

---

## 2. Presentación
El desperdicio de alimentos es un problema crítico de sostenibilidad. En este primer Sprint, desarrollará el producto mínimo viable (MVP) de **LastBite**, enfocado en la gestión del catálogo de paquetes en oferta y el ciclo básico de reserva con pago en punto de venta. Aplicará conceptos de modelado de bases de datos, desarrollo frontend responsivo y construcción de APIs/Backend.

---

## 3. Resultados de Aprendizaje (RAP) SENA
1. **RAP 01:** Construir la interfaz gráfica de usuario aplicando estándares de usabilidad, accesibilidad y diseño web responsivo.
2. **RAP 02:** Implementar la base de datos según el modelo lógico y físico validado para la aplicación.
3. **RAP 03:** Desarrollar los componentes backend para el manejo de CRUDs y persistencia de datos del sistema.

---

## 4. Actividades de Aprendizaje y Tareas

### Actividad 1: Modelado de Datos y Configuración (Semana 1)
* Diseñar el diagrama Entidad-Relación (E-R) o esquema NoSQL para: Usuarios (Comercio/Cliente), Productos/Paquetes y Reservas.
* Inicializar el repositorio Git con la estructura base de carpetas y control de versiones.

### Actividad 2: Frontend Responsivo y Maquetación (Semana 2)
* Maquetar el formulario de registro de comercios y publicación de ofertas.
* Construir la vista de catálogo general en Grid/Flexbox con tarjetas para cada paquete.

### Actividad 3: Desarrollo Backend y Persistencia (Semana 3)
* Implementar los endpoints/rutas para el CRUD de paquetes de comida.
* Configurar la conexión con la base de datos (MySQL / PostgreSQL / MongoDB).

### Actividad 4: Integración del Flujo de Reserva y Pruebas (Semana 4)
* Conectar el frontend con el backend para ejecutar la reserva con actualización de stock en tiempo real.
* Documentar las historias de usuario terminadas y preparar la demo del Sprint.

---

## 5. Entregables
1. **Repositorio Git:** Código fuente estructurado, con commits descriptivos e historial limpio.
2. **Documento Técnico:** Diagrama de Base de Datos y scripts de creación de tablas/colecciones.
3. **Mapeo de Historias de Usuario:** Archivos `.md` actualizados con criterios de aceptación cumplidos.
4. **Demostración Funcional:** Video o sustentación en vivo del flujo completo (Publicación -> Catálogo -> Reserva).
